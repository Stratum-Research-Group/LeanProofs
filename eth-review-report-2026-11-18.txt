THEORETICAL ARTIFACT CONFIRMED WITH SUBSTANTIAL FORMAL-TO-MODEL AND
PAPER-TO-LEAN TRANSLATION GAPS. NOT A GENERAL PRACTICAL SOLVER NOR A COMPLETE
END-TO-END AUTOMATED VERIFICATION OF ETH REFUTATION ON STANDARD MODELS OF
COMPUTATION.

The package publishes an asymptotic #3-SAT algorithm in 2^{O(n log log n / sqrt(log n))}
steps, formalizing two headline claims (`ETHIsFalse` and `MainTheorem`) in Lean 4.
However:
1. The formal model uses Mathlib's `FinTM2` (multi-stack Turing machine), leaving
   the simulation equivalence to word-RAM, random access machines, and standard
   computational models explicitly outside Lean.
2. `MainTheorem` requires strict formula conditions: variables x_0 ... x_{n-1}
   must all occur, no duplicate clauses, k >= 1, n >= 4, m >= 2. Deleting dummy
   variables changes #SAT counts by powers of 2, requiring delicate non-formalized
   classical preprocessing.
3. The Lean proof is NOT a step-for-step formalization of the printed paper:
   Section 6 and Algorithm 1 are formalized primarily in decision form rather than
   counting form, alternation overheads differ by polynomial powers, and intermediate
   cost models rely on arbitrary polynomial-time transition functions with state bounds.

STAGE A: SPECIFICATION CONTRACT AUDIT (MainResults.lean vs Paper Headline)
Status: COMPLETED (SOURCE-CONFIRMED)
--------------------------------------------------------------------------------
Audited file: eth/MainResults.lean (182 lines)

Contract Definition & Quantifiers:
- Quantifiers:
  * `ETHIsFalse`: ¬(0 < s 3), where s 3 is the infimum over delta >= 0 of machines
    M (with finite alphabets) deciding 3-SAT in floor(c * 2^{delta * n}) steps.
  * `MainTheorem`: ∃ (M : TM2ComputableAux Bool Bool) (C : ℕ), (∀ i, Finite (M.tm.Γ i)) ∧
    ∀ (k n : ℕ) (φ : CNF n), 1 ≤ k → IsKCNF k φ → 2 ≤ φ.length → 4 ≤ n → AllOccur φ →
    CountsWithin M k φ (timeMin C k φ.length n).
- Encoding:
  * k-SAT input: 1^k 0 followed by 1^n 0, then for each clause k slots of
    floor(log_2(2n)) + 1 bits (unary length headers + fixed-width bit slots).
- Restrictions & Bounds:
  * k >= 1, n >= 4, m >= 2.
  * Every variable in Fin n must occur in phi (`AllOccur φ`).
  * Clauses must not be duplicated (`φ.Nodup`).
- Informal Bridges Outside Lean:
  * RAM / Word-RAM to multi-stack Turing machine (FinTM2) simulation.
  * Standard formula representation (arbitrary CNF) to normalized encoding
    without isolated variables.

- Single-bit identity:
  X_1(x,y,u,v) = I_1(x,y,u,v) - s(x,y)*s(u,v)

================================================================================
PRIORITIZED DEFECTS AND LIMITATIONS
================================================================================

1. P1 (HIGH): Unverified Informal Bridge to Standard Computational Models
   - Module: eth/MainResults.lean:26-44, paper/paper.pdf:Appendix E
   - Confidence: Confirmed (Disclosed Limitation)
   - Condition: Lean proves bounds for Mathlib `FinTM2` multi-stack Turing machines.
     The reduction to RAM / word-RAM and Turing-machine equivalence is informal prose.
   - Impact: Machine verification alone does not formally guarantee ETH refutation
     in standard complexity definitions without the unproved simulator bridge.

2. P1 (HIGH): Structural Discrepancy Between Paper Proof and Formal Proof
   - Module: eth/proof/PaperIndex.lean:180-245
   - Confidence: Confirmed (Disclosed Divergence)
   - Condition: The paper claims Theorem 2 for counting, whereas the formal proof
     primarily routes through a deciding variant (Sat) and uses a non-uniform
     polynomial-step intermediate model before compiling to FinTM2.
   - Impact: Direct human audits of the paper's mathematical arguments cannot assume
     1:1 correspondence with Lean theorem lemmas without checking the compilation path.

3. P2 (MEDIUM): Missing Normalization & Non-occurrence Handling in Count Contract
   - Module: eth/MainResults.lean:177-181
   - Confidence: Confirmed
   - Condition: `MainTheorem` requires `AllOccur φ` and `φ.Nodup`.
   - Impact: Applying the algorithm to arbitrary CNF instances requires preprocessing
     isolated variables and duplicates. For counting problems, each omitted variable
     multiplies solutions by 2, requiring careful external accounting.
